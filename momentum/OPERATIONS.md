# Momentum: operations manual

How to deploy, change and look after the momentum app. For how it works, see
[README.md](README.md). All commands assume Git Bash (or any bash) with `gcloud` signed in as an
owner of the project, run from this `momentum/` folder.

```
PROJECT=arched-tape-447611-r0   REGION=asia-south1   ZONE=asia-south1-a
```

## Configuration

`infra/config.env` is copied from `infra/config.example.env` and is gitignored, so never commit it:

| Key | Meaning |
|---|---|
| `PROJECT_ID`, `REGION` | GCP project and region |
| `BUDGET_AMOUNT`, `BUDGET_CURRENCY` | Monthly budget alert on `app=momentum` spend (emails at 50/90/100%) |
| `OWNER_EMAILS` | Google accounts allowed into the portal (IAP and app-level check) |
| `SCHEDULE` | Cron for the weekly run, Asia/Kolkata (default `0 8 * * 6`) |
| `KITE_API_KEY` | Kite Connect API key (not secret) |

Strategy parameters (risk, caps, ranks, exclusion list, LIQUIDBEES parking) are edited on the
portal's **Settings** page and stored in `mom_settings/current`. They take effect from the next run.

## Secrets (Secret Manager)

| Secret | Who reads it | How it is created |
|---|---|---|
| `mom-kite-api-secret` | VM only | **By you**, never by Claude: `printf '%s' 'SECRET' \| gcloud secrets create mom-kite-api-secret --data-file=- --replication-policy=automatic --labels=app=momentum --project=$PROJECT` |
| `mom-relay-token` | VM and portal | Generated by `infra/deploy_kite.sh` and never printed |

To rotate the Kite secret, regenerate it on developers.kite.trade, then run
`printf '%s' 'NEW' | gcloud secrets versions add mom-kite-api-secret --data-file=-` and restart the
relay (see below). To rotate the relay token, run
`head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' | gcloud secrets versions add mom-relay-token --data-file=-`,
then restart the relay and redeploy the portal (`gcloud run services update mom-portal --region=$REGION --update-secrets=MOM_RELAY_TOKEN=mom-relay-token:latest`).

## Deploy

First time, or after infra changes (both scripts are idempotent):

```bash
bash infra/deploy.sh        # APIs, service accounts, image, job + schedule, portal (IAP), budget
bash infra/deploy_kite.sh   # secrets, relay on the VM, firewall, portal's private route to the relay
```

After a code change is merged to `main`:

```bash
TAG=$(date +%Y%m%d-%H%M%S); IMG=$REGION-docker.pkg.dev/$PROJECT/mom/app:$TAG
gcloud builds submit --project=$PROJECT --region=$REGION --tag=$IMG .
gcloud run jobs update mom-weekly --project=$PROJECT --region=$REGION --image=$IMG
gcloud run services update mom-portal --project=$PROJECT --region=$REGION --image=$IMG
# relay changes only:
gcloud compute ssh mom-kite-vm --zone=$ZONE --tunnel-through-iap --project=$PROJECT \
  --command="sudo google_metadata_script_runner startup"
```

The relay installs from the branch in the VM's `relay-branch` metadata (default `main`). To try an
unmerged branch, run `gcloud compute instances add-metadata mom-kite-vm --zone=$ZONE --metadata=relay-branch=<branch>`.
Then run the startup script again, and set it back to `main` afterwards.

Artifact Registry keeps the 3 newest images, so you can roll back by updating the job and portal
to an older tag from `gcloud artifacts docker images list $REGION-docker.pkg.dev/$PROJECT/mom/app`.

## Running and checking the weekly job

- **Run now:** use the portal's **Run the weekly review now** button, or
  `gcloud run jobs execute mom-weekly --region=$REGION --wait --update-env-vars=MOM_FORCE=1`.
  `MOM_FORCE=1` recomputes even a signed-off week. Don't use it after you've signed off unless you
  mean to.
- **Logs:**
  `gcloud logging read 'resource.type="cloud_run_job" AND resource.labels.job_name="mom-weekly"' --limit=80 --freshness=1d --format="value(textPayload)"`.
  The portal's **Runs** page shows the same log tail.
- **Change the schedule:** set `SCHEDULE` in `config.env` and re-run `deploy.sh`, or run
  `gcloud scheduler jobs update http mom-weekly-schedule --location=$REGION --schedule="0 8 * * 6"`.
  Then update `MOM_SCHEDULE` on the portal so its "next run" line matches.
- **Pause:** `gcloud scheduler jobs pause mom-weekly-schedule --location=$REGION` (`resume` to undo).
- **Expected noise:** NSE's list contains a placeholder `DUMMYHEG` with no prices, so the price
  count is normally one or two below the universe.

## The daily Kite login

Kite access tokens expire at **06:00 IST** every day. Before using the Zerodha page, press
**Connect Zerodha**, sign in on Zerodha's page, and you are sent back to the portal. The Kite
app's Redirect URL must be `https://mom-portal-685089913713.asia-south1.run.app/kite/callback`
(developers.kite.trade → My apps → Momentum). If the portal URL ever changes, update it there.

**Test order:** it places 1 LIQUIDBEES at 3% under its last price and cancels it straight away. If
Kite ever shows it as COMPLETE, you simply hold 1 unit of LIQUIDBEES. Sell it or leave it parked.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| Portal shows 502 "Empty Google Account OAuth client" | Project-wide IAP OAuth settings were lost: re-apply with `gcloud iap settings set iap.yaml --project=$PROJECT` (the client ID/secret are in the file you saved when creating the OAuth client) |
| Portal 403 "Not authorised" | The signed-in Google account isn't in `MOM_ALLOWED_USERS` / IAP. Add it to `OWNER_EMAILS` and re-run `deploy.sh` |
| Run failed: "could not download the Nifty 500 list" and no cache | NSE blocked the request. Retry later; once one run succeeds the list is cached |
| Many symbols missing prices | Yahoo rate limiting. Re-run later; if it persists, Kite Connect's paid plan (historical data) is the upgrade path |
| Zerodha page: "Could not reach the Kite relay" | VM stopped, relay down, or firewall/VPC route missing. Check `gcloud compute instances list`, then `gcloud compute ssh mom-kite-vm --zone=$ZONE --tunnel-through-iap --command="systemctl status mom-relay; journalctl -u mom-relay -n 50"`, then re-run `deploy_kite.sh` |
| "Not connected today" / "session has expired" | Do the daily Connect Zerodha login |
| Kite "IP not allowed" / InputException on orders | The static IP changed or isn't whitelisted: confirm `gcloud compute addresses describe mom-kite-ip --region=$REGION` is 34.93.168.72 and matches the Kite developer profile |
| Login fails with checksum/TokenException | The API secret in Secret Manager doesn't match the Kite app. Add the correct version and restart the relay |
| Budget alert email | See Costs below; check that nothing unexpected carries `app=momentum` |

The `mom-monthly-arched-tape-447611-r0` budget (₹1,500) emails at 50/90/100%. It alerts only and
doesn't stop anything. Stopping the VM saves the VM cost, but Zerodha orders and checks stop working.

## Safety rules for future changes

- Nothing may place a real strategy order without the owner's explicit decision. The relay's only
  order path is the cancelled test order. Any new order endpoint must require a per-order
  confirmation in the portal and carry the `Momentum` tag.
- Never commit `infra/config.env`, secrets or access tokens. The repo is **public**.
- Keep every GCP resource named `mom-*` and labelled `app=momentum`. Never modify `mb-*`
  resources, which belong to the multibagger app.
- Use only `mom_*` Firestore collections. Multibagger owns the unprefixed ones; this app only
  *reads* `fundamentals` and `control/fundamentals`.
- Run `python -m pytest -q` before every deploy.
